現在のブランチのPRに来ているレビューコメントを確認して、指摘事項を修正します。以下の手順で進めてください。

## 手順

### 1. PRレビューの取得

以下を実行してレビューコメントを取得してください：

```bash
gh pr view --comments
gh pr view
# 行に付いたコメント（ファイル・行番号つき）は上の 2 つには出ない
gh api --paginate "repos/{owner}/{repo}/pulls/$(gh pr view --json number -q .number)/comments?per_page=100" \
  --jq '.[] | "\(.user.login) \(.path):\(.line // .original_line)\n\(.body)\n"'
```

### 2. 指摘事項の整理

取得したコメントを以下の観点で分類して表示してください：

- 🔴 **必須修正**: バグ・セキュリティ・設計上の問題
- 🟠 **要対応**: 品質・可読性・規約違反
- 🟡 **Minor**: 提案・Nit

github-actions bot のコメントはチェック結果として扱い、指摘ではなくレビューの補足情報として参照してください。

```
## 📋 PRレビュー #[番号] — [タイトル]

### [重要度] [概要]
- **ファイル**: [file:line]
- **内容**: [指摘の要約]
```

### 3. 修正

指摘事項を上から順に修正してください：

1. 対象ファイルを必ず読んでから変更する
2. 修正内容はシンプルに、指摘された箇所のみ変更する。アプリのコードを大きく直すときは、`implementer` に渡す
   （指摘・失敗シナリオ・修正方針を `ai-plan/` のプランに書く）
3. 全指摘の修正が終わったら `bun run check-all` で確認

### 4. 報告

修正完了後、以下の形式で報告してください：

```
## ✅ 修正完了

- [指摘1]: [対応内容]
- [指摘2]: [対応内容]
```

### 5. ルール更新の検討

報告の後、今回の指摘を振り返って以下を評価してください。

**ルール化すべき判定基準（すべて満たす場合に提案する）:**
1. 今回の指摘が「事前にルールがあれば防げた」バグ・設計ミスを含む
2. 同種の指摘が今後も繰り返されそうなパターンである
3. ルートの規約（`CLAUDE.md` と取り込んでいるファイル）・`.claude/rules/` の既存ルール、`.claude/commands/codex-review.md` の既存チェック項目、`scripts/check/` の既存ガードのいずれにも対応する記述がない

該当する場合は以下の形式でまとめる。規約文の追加は確認を待たず同じ PR に追加コミットする（本文に追加した理由を残す）。
ガード（`scripts/check/`）や `scripts/check/verifier-paths.txt` に当たるファイルへの追加は、その PR に足さず別 issue に切り出す
（レビュー中の PR に検証器の変更が入ると、収束が遅れ、PR 本文の「検証器の変更理由」も要る）：

```
## 📝 ルール追加の提案

### [提案1]
- **追加先**: 機械検査できるなら `scripts/check/arch-guards.sh` 等、レビュー時に確認すれば足りるなら `codex-review.md` の Step 3-X、それ以外は効く範囲の規約ファイル（always-loaded の `general.md` は最後の選択肢）
- **追加内容**:
  （具体的なルール文・コード例）
- **根拠**: 今回の指摘で判明した問題と、ルールがあれば防げた理由
```
