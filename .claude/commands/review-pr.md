現在のブランチのPRに来ているレビューコメントを確認して、指摘事項を修正します。以下の手順で進めてください。

## 手順

### 1. PRレビューの取得

以下を実行してレビューコメントを取得してください：

```bash
gh pr view --comments
gh pr view
```

### 2. 指摘事項の整理

取得したコメントを以下の観点で分類して表示してください：

- 🔴 **必須修正**: バグ・セキュリティ・設計上の問題
- 🟠 **要対応**: 品質・可読性・規約違反
- 🟡 **Minor**: 提案・Nit

github-actions bot のコメントはチェック結果として扱い、指摘ではなくレビューの補足情報として参照してください。

```
## 📋 PRレビュー #[番号] — [タイトル]

### [重要度] [概要]
- **ファイル**: [file:line]
- **内容**: [指摘の要約]
```

### 3. 修正

指摘事項を上から順に修正してください：

1. 対象ファイルを必ず読んでから変更する
2. 修正内容はシンプルに、指摘された箇所のみ変更する
3. 全指摘の修正が終わったら `bun run check-all` で確認

### 4. 報告

修正完了後、以下の形式で報告してください：

```
## ✅ 修正完了

- [指摘1]: [対応内容]
- [指摘2]: [対応内容]
```

### 5. ルール更新の検討

報告の後、今回の指摘を振り返って以下を評価してください。

**ルール化すべき判定基準（すべて満たす場合に提案する）:**
1. 今回の指摘が「事前にルールがあれば防げた」バグ・設計ミスを含む
2. 同種の指摘が今後も繰り返されそうなパターンである
3. `CLAUDE.md` の既存ルール、または `.claude/commands/codex-review.md` の既存チェック項目に対応する記述がない

該当する場合は以下の形式で提案し、AskUserQuestion でユーザーに確認を取ること：

```
## 📝 ルール追加の提案

### [提案1]
- **追加先**: `CLAUDE.md`（または `codex-review.md` の Step 3-X）
- **追加内容**:
  （具体的なルール文・コード例）
- **根拠**: 今回の指摘で判明した問題と、ルールがあれば防げた理由

この内容を追記しますか？
```

ユーザーが承認した場合のみ該当ファイルを更新してください。
