# PRD — 定員付きグループイベント予約サービス

## 1. プロダクト概要

**ワンライナー**
モダンで埋め込み可能な、定員付きグループイベント予約サービス。

**解決する課題**
社内説明会・採用説明会・セミナーなどのオフライン/オンラインイベントを定員制で受け付けるニーズに対し、既存サービスはいずれか一つが欠けている。

- UIが古くて使いにくい（Peatix, SELECTTYPE, EventRegist）
- 外部連携（webhook / Zapier / スプレッドシート）がない or 弱い
- iframe埋め込みが不便、または自社サイトへの統合が難しい
- エンタープライズ向けで高価格・オーバースペック（Oniva, Eventboost）

本プロダクトはこのギャップを埋める。

---

## 2. ターゲットユーザー

**主なユーザー**
- 企業の人事・総務担当者（社内説明会、採用説明会を定期開催）
- セミナー・勉強会の主催者（外部に自社サイトを持ち、そこに埋め込みたい）

**ターゲット市場**
未定。日本市場をファーストターゲットとしつつ、グローバル展開の可能性も残す。初期のUIは日本語で実装し、i18n対応は後から追加可能な設計とする。

**ペルソナ例**
- 人事担当者（30代）が月2回、会社説明会を開催している。申込管理はGoogleフォーム + スプレッドシートで手動管理しており、定員オーバーの気づきが遅れることがある。自社採用サイトに埋め込める定員管理ツールを探している。

## 4. 機能要件

### P0 — MVP（必須）

#### イベント管理
- イベントの作成・編集・削除・公開/非公開の切り替え
- 設定項目: タイトル、説明、開催日時、開催場所（任意）、定員数
- 定員に達した時点で申込を自動で締め切る

#### 申込フォーム
- 最低限の項目: 名前、メールアドレス
- 送信前に定員チェック（同時申込の競合を防ぐ楽観ロック or トランザクション）
- 同一メールアドレスによる重複申込はエラー（「このメールアドレスはすでに申込済みです」）
- 申込完了後に確認画面を表示

#### キャンセル
- 申込者: 申込完了メールに含まれるキャンセルリンクから自分でキャンセル可能（P1メール通知と同時実装）
- 主催者: 管理画面から個別にキャンセル（削除）可能
- キャンセル後は定員に空きが戻り、新規申込が可能になる
- ブラックリスト機能は将来対応（P2）

#### iframe埋め込みウィジェット
- イベントごとに埋め込み用コードを発行（`<iframe>` 1行でOK）
- 外部サイトに埋め込まれた状態でも申込フローが完結する
- レスポンシブ対応
- 申込完了後のリダイレクト先URLをイベントごとに設定可能（未設定時はデフォルトのサンクス画面を表示）

#### 管理画面
- イベント一覧（ステータス: 受付中 / 満席 / 終了）
- 申込者一覧（氏名、メール、申込日時）
- 申込者リストのCSVエクスポート

### P1 — Should（次フェーズ）

- **メール通知**: 申込完了時の自動確認メール（申込者宛）
- **リマインドメール**: 開催前日に自動送信
- **ウェイトリスト**: 定員超過時に待機登録。キャンセルが出た場合に繰り上げ通知

### P2 — Nice to have（将来）

- **webhook**: 申込発生時に指定URLへPOSTリクエストを送信
- **Zapier連携**: Zapierアプリとして登録し、5,000以上のアプリと連携
- **Google Sheets連携**: 申込データをリアルタイムでスプレッドシートに書き込む
- **決済**: Stripe連携による有料イベントの対応
- **カスタムフォーム項目**: 質問の追加（テキスト、選択肢）

## 5. 非機能要件

**パフォーマンス**
- 申込フォームの表示: 1秒以内
- 申込送信から完了画面: 2秒以内

**セキュリティ**
- スパム申込対策（レートリミット、必要に応じてhCaptcha）
- SQLインジェクション / XSS 防止はフレームワーク標準機能で対応

**アクセシビリティ**
- フォームはキーボード操作完結・スクリーンリーダー対応（WCAG 2.1 AA 準拠を目標）

**スケーラビリティ**
- 複数の主催者が共存するマルチユーザー構成（共有DB）。データ分離はRLSで実現（`user_id` フィルタ）
- チーム機能（複数ユーザーで1組織を管理）はP2対応

## 5.5 認証設計

**採用: [Better Auth](https://better-auth.com/)**

選定理由:
- TanStack Start / Hono 両方に公式インテグレーションがある
- ユーザーデータが自前の PostgreSQL に格納される（申込者データと同じDBで一元管理可能）
- オープンソース・自己ホスト → ベンダーロックインなし、MAU課金なし

**認証方式（MVP）**
- メール + パスワード（イベント主催者のアカウント登録・ログイン）
- 申込者はアカウント不要（メールアドレスのみで申込可能）

**アクセス制御**
- ログイン済みユーザーのみ: イベント作成・編集・削除、申込者一覧閲覧
- 未ログインでも可: イベント詳細閲覧、申込フォーム送信（iframe経由含む）

## 6. 収益モデル

フリーミアム。アップグレードの主な動機は**チームでの利用**と**外部連携（webhook）**。

| プラン | 制限 | 価格 |
|---|---|---|
| Free | メンバー1人、アクティブイベント3件 | 無料 |
| Pro | メンバー無制限、イベント無制限、webhook | ¥2,980/月 |

**共有アカウント問題について**

1つのアカウントをチームで共有されるケースは防ぎきれないが、以下の機能が「自然なアップグレード動機」として機能する：
- 操作ログ・変更履歴（誰が何をしたかわからない）
- 通知の個別設定（申込通知が一人にしか届かない）
- イベントごとの権限管理

**MVP 段階では全機能無料で提供し、課金導線は実際に使われてから実装する。**

## 7. 技術スタック

このリポジトリのテンプレートをベースに構築する。

| レイヤー | 技術 | 備考 |
|---|---|---|
| フロントエンド | TanStack Start + React 19 + Tailwind v4 | |
| バックエンド | Hono（TanStack Start の Server Route にマウント） | CORS 不要、単一デプロイ |
| ORM | Drizzle | エッジネイティブ、Cloudflare 対応 |
| DB | Supabase（PostgreSQL, ap-northeast-1 Tokyo）| Cloudflare Hyperdrive 経由で接続 |
| 認証 | Better Auth + better-auth-cloudflare | Cloudflare Workers 対応の設定が必要 |
| メール送信 | Resend | P1（メール通知実装時） |
| デプロイ | Cloudflare Workers（単一） | |

**デプロイ構成**

`apps/api-service`（Hono）と `apps/client`（TanStack Start）はモノレポ内で独立したパッケージとして開発するが、デプロイは1つの Cloudflare Worker にまとめる。`client` の `app/routes/api/$.ts` が `api-service` の Hono app をマウントする1ファイルを追加するだけで実現できる。

```
Cloudflare Workers（1つ）
├── /                    # 管理ダッシュボード（TanStack Start）
├── /events/[id]         # イベント公開ページ
├── /embed/[id]          # iframe widget（frame-ancestors ヘッダーをここで制御）
└── /api/*               # Hono がハンドル（Clean Architecture はここで完結）
```

**iframe セキュリティ**

- `/embed/[id]` ページは `Content-Security-Policy: frame-ancestors <許可ドメイン>` ヘッダーを返す
- 許可ドメインはイベント作成時に設定可能。未設定時は `*`（どこでも埋め込み可）
- 管理画面など埋め込まれたくないページには `X-Frame-Options: DENY` を設定

## 8. MVP 成功指標

- [ ] イベントを作成・公開できる
